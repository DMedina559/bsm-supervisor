BSM Supervisor Experimental

Service & recovery console

Connect to your supervisor

This supervisor is experimental. Validate recovery before using important server data.

Use the console access token created inside your container. Your BSM account is separate.

Overview

BSM service

Start checks the managed process. Application readiness is verified separately with the health command.

Version management

Use stable, prerelease, or an exact version such as 4.0.0b7. Installation IDs belong in the selector below.

Recovery checkpoints

Creation and restoration require BSM to be stopped.

Recovery

Inspect the history and current service state before acknowledging anything. Acknowledgement does not restore data.

Operations

Console jobs

Progress



Backups
Create a verified checkpoint of the database, configuration and configured data. A running BSM is stopped gracefully and restarted after successful capture.


Download & upload
Supply the original password for encrypted uploads. Passwords are used for this operation only. Unencrypted archives contain private BSM data.
Import verifies the archive and adds a checkpoint. It never restores data automatically. Transfers expire after 24 hours.


Checkpoint inspection
Choose a checkpoint to inspect its database, version and storage coverage.


Retention
Pinned backups and recovery checkpoints for installed versions remain protected.


Schedules
Policy details
Create or edit schedule
Export and journal retention options
Schedules use UTC, skip missed windows, and retain recovery blockers. Saving an existing name replaces its owned policy and timer.


Notifications
Webhook URLs are concealed. Notifications contain completion IDs, state and timestamps. Use a notification schedule for automatic delivery.


Supervisor & BSM settings
Runtime listener and database changes require BSM to be stopped. Save refreshes its generated unit and leaves BSM stopped. Proxmox environment overrides are shown and must be edited at their source.
Storage paths and managed service
Storage relocation and console listener/origin changes require host configuration so an incorrect change cannot strand this console.


Supervisor updates
latest selects a stable release. Choose an explicit beta tag or dev for prerelease builds. Updates may stop and restart BSM.
Finish jobs before restarting the console. After updating, restart the console to load its new code, then reload and reconnect. Custom service units require a host restart command.
Diagnostics & cleanup
Cleanup requires BSM to be stopped and the restore transaction to be resolved.


Action output
Choose an action to see its result here. Operation history remains under Overview.


Restore BSM data
This replaces saved database, configuration and data with the chosen checkpoint. Newer changes are discarded. A pinned recovery checkpoint will be captured first.
Partial database-only restoration is unsupported because it can leave configuration and server files inconsistent.
