         Supervisor & BSM settings
        

       

       

        Runtime listener, database and lifecycle changes require BSM to be stopped. Save refreshes its generated unit and leaves BSM stopped. Proxmox environment overrides are shown and must be edited at their source.

           Supervisor & lifecycle
          

          
          
          
          
          
          
          

           Requires the standard bsm-supervisor-console.service. Stop BSM before changing this setting. Console restarts stop BSM too; automatic startup controls whether it starts again.
          

         

        

        
       

       

        
         Storage paths and managed service
        
        

       

       

        Storage relocation and console listener/origin changes require host configuration so an incorrect change cannot strand this console.
       

      

     

     

      

       

        

         
          
         
         

          Supervisor updates
         

        

        

        
        
        

         latest selects a stable release. Choose an explicit beta tag or dev for prerelease builds. Updates may stop and restart BSM.
        

        
        

         
         
         
        

        

         Finish jobs before restarting the console. After updating, restart the console to load its new code, then reload and reconnect. Custom service units require a host restart command.
        

       

       

        

         
          
         
         

          Diagnostics & cleanup
         

        

        

         
         
         
        

        
        
        
        
        

         Cleanup requires BSM to be stopped and the restore transaction to be resolved.

       Restore BSM data
      

      

       This replaces saved database, configuration and data with the chosen checkpoint. Newer changes are discarded. A pinned recovery checkpoint will be captured first.
      

      

      
      

       Partial database-only restoration is unsupported because it can leave configuration and server files inconsistent.
